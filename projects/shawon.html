Talking-Video Portfolio — a hero that introduces me

A second take on this portfolio, built as a TanStack Start application. The hero is a talking 3D avatar with a synced voice track; the rest is a set of small, self-contained interactions that make the page feel alive without getting in the way.

Overview

This is the same content as the static portfolio, rebuilt on a modern stack so I could try ideas the no-build version could not carry: a video hero, a physics-driven ID card, and a skills table that behaves like the periodic table. It is a TanStack Start application — React with a typed router and server-side rendering — but it ships as plain static HTML to GitHub Pages.

The reason it is a separate repository rather than a replacement is deliberate. The static site is the dependable one: it has no dependencies to patch and nothing to build. This one is where the experiments live, and it is free to be the more ambitious of the two.

Problem and solution

The problem

A portfolio that only lists skills is easy to skim past. I wanted a first impression that a visitor cannot get from a paragraph — something that shows the work by being the work. The obvious answer is a video, but a raw video fights every rule of a good landing page: it is heavy, it does not autoplay with sound, and it distracts from the content underneath.

The solution

A single talking-avatar clip that loops seamlessly, tries to autoplay with sound, falls back to muted when the browser refuses, and offers one clear control to turn the voice back on. Everything below the fold stays quiet: the ID card swings from a fixed point like a real lanyard, and the skills table only reacts when you point at it.

The rule carried over from the static site: the page must be complete before any of it runs. The video, the pendulum and the glows are all enhancements. Turn off JavaScript and the content is still there and still readable.

Key features

01

A talking 3D avatar hero

The hero is a 9-second clip of a 3D character introducing me in his own voice. It loops with no visible jump, and the voice is behind a single button so it never surprises a visitor.

02

Audio that waits for consent

The clip first tries to play with sound; if the browser blocks it, it falls back to muted and unlocks the voice on the visitor's first interaction — unless they have already chosen to mute it.

03

A physics lanyard ID card

The developer badge hangs from a damped pendulum, so it swings when you drag it and settles naturally instead of snapping back.

04

A periodic table of skills

Each technology is a tile in the table of the stack. Point at one and a panel shows where it was actually used, so the list is evidence rather than decoration.

05

Server-rendered, statically hosted

TanStack Start renders the page on the server and prerenders it to HTML, so it is fast on first paint — then a GitHub Actions workflow publishes the static output to GitHub Pages.

Architecture

One application, split into routes, components and a small data layer, built by Vite and prerendered by TanStack Start. 

src/
  routes/                File-based routes — one page per section
  components/portfolio/  Hero, About, Skills, Work, Experience, Contact
  lib/data.ts            Every string and link, in one place
  assets/hero/           The avatar clip and its still, referenced by manifest
public/                  favicon, the résumé PDF and the hero clip
.github/workflows/       Build, test and deploy to GitHub Pages
vite.config.ts           BASE_PATH lets the same code run at / and /Shawon-/

One data file, no copy in components

Every fact the site states — the name, the roles, the project links, the résumé path — lives in src/lib/data.ts. Components read from it and never hard-code a string. Changing a job title is a one-line edit in one file, and nothing can drift out of sync with itself.

The same code, two base paths

A GitHub Pages project site is served from a subdirectory (/Shawon-/), not from the root. The build reads a BASE_PATH environment variable and threads it through the router and every asset URL, so the identical code runs at / in development and at /Shawon-/ in production.

Challenges and what I learned

Autoplay with sound, without being obnoxious

Browsers will not let a page start talking on its own, and they are right not to. The first version simply muted the video when autoplay was refused and left it that way, which threw away the whole point of a talking avatar.

The fix was to treat the sound as a state machine: try unmuted, fall back to muted, and then listen for the visitor's first deliberate interaction to restore the voice — but only if they have not already pressed mute themselves. The button is the single source of truth for that choice.

A looping clip that does not visibly jump

A talking-head clip cut to a hard loop shows a jump every time it restarts. Rather than accept it, the loop is built in a preprocessing step: the last half-second cross-fades into the first half-second, for the picture and for the audio, so the seam is invisible and inaudible.

Static hosting for a server-rendered app

TanStack Start is built for a server. GitHub Pages only serves files. The answer is prerendering: the build renders the page to plain HTML at build time, and the deploy workflow publishes that HTML plus the assets. The result is a modern, typed codebase that still costs nothing to host.
