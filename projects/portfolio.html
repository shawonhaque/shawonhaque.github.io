This portfolio — no framework, no build step

A static site in semantic HTML, modern CSS and vanilla JavaScript. The interesting problems were not the layout — they were the details that decide whether a site actually works for everyone who opens it.

Overview

The site is one page — hero, about, expertise, projects, experience, resume and contact — plus a custom 404 and this set of inner pages. There is no framework and no build step: what is in the repository is what the browser receives.

That was a deliberate choice, not a limitation. A portfolio is mostly static content with a small amount of interaction. A framework would have added a build pipeline, a dependency tree to keep patched, and a bundle to download — all to render text and a few cards.

Problem and solution

The problem

A developer portfolio has to do a specific job: convince a stranger, in under a minute, that the person behind it is careful. That makes the failure modes unusually costly — a broken link, a layout that collapses on a phone, a theme that flashes white before it loads, or a resume that will not open all undercut the claim the site is making.

The solution

Treat the unglamorous details as the feature. Every interactive element is keyboard reachable, both themes ship with system detection, the resume is a real PDF that renders in every reader, and the whole thing works with JavaScript switched off.

The rule I set myself: nothing on the page may depend on an effect that might not run. Animation, WebGL and smooth scrolling are all additive. Remove any of them and the site is still complete.

Key features

01

Light and dark themes

Applied before the first paint by a small inline script, so there is no flash of the wrong theme. The choice persists, and falls back to the system preference.

02

Accessible by default

Skip link, one h1 per page, semantic landmarks, visible focus states, ARIA labels on icon-only controls, and a full prefers-reduced-motion path.

03

Complete SEO and social metadata

Descriptive titles, canonical URLs, Open Graph and Twitter cards, JSON-LD structured data, robots.txt and a sitemap.

04

A contact form that cannot silently lose a message

It posts to a relay service; if that is unreachable, it opens the visitor's mail client with the message already written.

05

A resume PDF that renders everywhere

Generated from an HTML source, then post-processed — see the note on colour space below.

Architecture

Three layers, kept separate: markup, a token-driven stylesheet, and a small progressive-enhancement script.

                         experience, resume, contact
404.html                 Custom not-found page
projects/                Case studies (this page)
assets/
  css/styles.css         Design tokens, layout, components, print styles
  js/main.js             Theme, navigation, scroll, form — all guarded
  js/motion.js           Optional WebGL hero and scroll effects
  js/vendor/             Lenis, GSAP, ScrollTrigger, Three.js — committed
  img/                   WebP with JPEG or PNG fallbacks
  resume/                resume.html source → Shawon-Haque-Resume.pdf
tools/build-resume.py    Renders the resume and fixes its colour space

One stylesheet, driven by tokens

Colours, spacing, radii and the type scale are CSS custom properties. The two themes are just two sets of values for the same tokens, so a component never needs to know which theme is active. Adding the case-study pages you are reading meant adding new components that consume the existing tokens — not a second design system.

JavaScript as an enhancement

Every script is deferred, and every feature checks for the element it needs before touching it. The page is readable and navigable with JavaScript disabled; the script only adds smooth scrolling, the reveal animation, the theme toggle and the form handling.

Challenges and what I learned

A resume photo that vanished in some readers

The resume PDF showed the photo on my machine and a blank space on others. The cause was not the image — it was the colour space. Chrome had written it as /ColorSpace [/ICCBased …] with a Chrome-specific profile and no alternate, and small PDF engines, including the one in many mobile viewers, have no ICC support. They do not approximate the image; they drop it.

The fix was to rewrite the colour space as /DeviceRGB in a post-processing step, and to verify the result in five independent renderers rather than one. The lesson was that "it works on my machine" is a statement about my renderer, not about the file.

An animation that hid the page

When I added scroll-driven animation, the first version set elements to opacity: 0 as the tween was created and revealed them when a scroll trigger fired. If a trigger never fired, the content simply stayed invisible. Setting immediateRender: false fixed it: the element keeps its normal appearance until its animation actually starts.

The way I caught it was by rendering the page with JavaScript disabled and comparing. That is now a habit — the enhanced page must look the same as the plain one.

Deciding what not to ship

An alternative version of this site used CSS-drawn shapes as project thumbnails. They looked tidy and meant nothing: they were illustrations of projects rather than the projects. I replaced them with real screenshots. The same reasoning removed a decorative statistic and a certification section I could not yet back up.
